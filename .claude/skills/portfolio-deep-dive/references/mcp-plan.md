# MCP 逐笔三源对齐计划（Workflow 流水线 · 债当现金分池）

## 目标

对每笔 `ds + code + price` 逐笔对齐当天的三源快照，不拿当前估值套历史交易。**准确优先，主线程不堆 raw**。

## 流水线

### Phase 0 · 准备（主线程，不并行）

- 分池标记：按 `config.yaml:pool` 将交易标的标为 `risk`（股票+宽基/行业ETF）或 `cash`（债ETF 511xxx/159xxx + 货币/短融）。现金池不参与三源对齐，仅作现金管理统计。
- 选样：Top N 全量（持仓Top5 + 换仓高频Top3 + 归因Top3，去重后约12只风险池标的）逐笔全量对齐；其余风险池标的抽样（每标的每月最多2笔），保证覆盖率同时控 token。
- 输出选样清单与去重后的 `as_of` 列表，转 Phase 1。

### Phase 1 · 并行抽取（Workflow 4组，每组只回结构化摘要）

| 组 | 负责 | 输入 | 工具 | 输出（1-2KB JSON） |
|---|---|---|---|---|
| A | 风险池 2-3只 全量逐笔 | code + ds 列表 | `get_kline(day)` + `get_stock_detail(partial, as_of=ds)` | 每笔 `{ds, code, 技术分位, 买前5/20日涨跌, PE/PB/股息分位}` |
| B | 风险池 2-3只 全量逐笔 | 同上 | 同上 | 同上 |
| C | 风险池 2-3只 全量逐笔 | 同上（ETF/港股预期 bars==[]，记缺失） | 同上 | 同上（缺失标覆盖率） |
| D | 市场资金流（非个人账户资金） | 去重 as_of 列表（约150） | `get_fundflow(as_of)` + `get_index_fundflow(as_of)` | 每日 `{as_of, 主力净流入强度, 板块资金流}` |

**约束**
- 每组只回固定 Schema 的摘要，不回 raw JSON（4MB→20KB，主线程不污染）。
- 以 `(code, as_of)` 为 key，三源各缓存一份，24h 内不重拉；同一 `code+as_of` 多笔交易只拉一次。
- 任一返回 `409 CACHE_MISS` 或 `bars==[]`，记缺失，不重试 `refresh_stock`，在报告中标注覆盖率。
- 禁止并发批量 `diagnose_stock`；AI 诊断仅用户明确说「诊股/打分」时单只调，默认不走。

### Phase 2 · 聚合（主线程，不并行）

- 汇总4组摘要 → 算 D5 三源锚定度（技术/资金流/基本面各占比）→ D6 多维变点（方向/位置/资金流锚/估值锚/速度）→ D7/D8(速度轴：快杀 vs 扛单分群) → D9画像 → 组装 PDF。
- 相互验证：同一 `as_of` 的 K线与资金流需日期一致，不一致则标「口径差异」。

## Schema（Phase 1 摘要固定字段）

```json
{
  "code": "600941",
  "trades": [{"ds":"2025-02-28","side":"买入","price":107.09,"abs_amt":10709,"tech_pct":0.82,"pre5":0.03,"pre20":-0.05,"pe_pct":0.32,"pb_pct":0.45,"dv_pct":0.71}],
  "coverage": {"kline": "33/33","valuation":"30/33","fundflow":"—"}
}
```

## 覆盖率标注

- 报告 D5 章需显式 `K线 X/Y · 估值 X/Y · 资金流 X/Y`，任一 <60% 时结论加「样本不足」水印
- 单池与全池的覆盖率分开报告
- Phase 1 每组需自检 Schema 完整性，缺字段即重跑该组，不污染主线程

## 为什么必须 Workflow 并行

- 单股 `detail` 270KB ×12 + `kline` 63KB ×12 ≈4MB raw，全堆主线程会稀释后续变点与画像推理，准确性下降。
- 并行后主线程只吃 ~20KB 摘要，变点聚类与画像不受噪声干扰，且每组可独立校验。
