# Portfolio Deep Dive — 深度持仓解剖

> 目标：把任意一份「持仓 + 已清仓 + 交易流水」Excel，按同一套可复现的流水线，剖出金额真相、形态类型、资金三态、换仓指纹、买卖点三源对齐、阶段演进、归因与纪律画像，最终落为一句人话画像 + 一份可打印的 PDF 大报告。拒绝笔数陷阱与日历硬切。

## 铁律（由用户 critique 沉淀，违反即为缺陷）

1. **换仓按金额，不按笔数**：Top 榜、占比、强度一律金额加权。笔数仅作辅助标注，不作排序。
2. **债当现金，分池计算**：风险池（股票+宽基/行业ETF）与现金池（债ETF 511xxx/159xxx + 货币/短融 511620/511360）分开算。HHI/重叠/周转只在风险池内算；现金池单给「现金管理效率」。卖债买股=加仓，卖股买债=减仓，风险池内互换才是换仓。汇总用波动加权（债×0.1），511360 短融按货币。
3. **阶段不预设剧本**：禁止写死「接飞刀→筑底」「追涨→杀跌」等固定分期。变点由多维行为向量的聚类自动找，哪条轴突变就定哪种名。
4. **三源解耦，不假设人看什么**：技术/市场资金流/基本面三源分开度量，通过流水逐笔对齐当天快照反推锚定度，不假设投资者看哪一源。
5. **个人账户资金 ≠ 市场资金流**：前者归 D1（充值/提现/单笔占比），后者归三源之一（主力净流入/资金流强度，get_fundflow）。
6. **追涨内部用速度轴分开**：快杀 vs 扛单不在标签层面一刀切，用持有天数+亏损割肉天数自然分群。
7. **所有标签由聚类生成，不查表贴标签**：禁止先写 4 套剧本再往里套数据。
8. **准确优先，Workflow 并行控上下文**：三源快照抽取必须用 Workflow 并行分组，每组只回结构化摘要（1-2KB），主线程只吃摘要，不堆 4MB raw。单线程全量堆上下文者判为偷懒。

## 何时触发

- 用户给出文件路径（`*.xlsx / *.csv / *.xls`），或说「这是我的持仓/交易/清仓信息」
- 关键词：`持仓分析 / 投资画像 / 交易习惯 / 换仓 / 买卖点 / 阶段变化 / 风格 / 胜率 盈亏比 / 周转率 / 越跌越补 / 追高抄底 / 估值锚`
- 任何需要「不只看笔数、要看金额与仓位、要看换仓合理性、要分阶段、技术+估值双验」的诉求
- 只要用户说「详细」「深度」「不片面」「通用」「别人也能用」——用本 Skill，而不是随手跑一段统计

## 输入归一化

1. 自动识别三表：`持仓|在持|持仓数据` / `已清仓|已平仓|历史持仓` / `交易记录|流水|对账单|交割单`
2. 兼容表头别名（券商差异）：`代码/证券代码`、`名称/证券名称`、`发生金额/成交金额/金额`、`交易类别/业务类型` 等
3. 口径清洗：剔除 `GC回购/质押回购/银证转账/银行转存/股息个税/除权除息/新股入帐` 等非证券买卖流水对「买卖金额」的污染
4. 金额口径统一用 `成交金额绝对值`；买入在原表多为负，统一取绝对值后再算净额
5. 分池标记：按代码前缀与清单将每条流水标为 `risk` 或 `cash`（见 config.yaml 的 pool 规则）
6. 缺失容忍：没有「已清仓」也能跑（仅持仓+流水）；没有 K线/估值也能出技术分位版，估值分位标记为 `暂缺`

## 9 维度执行手册（三级落地）

> 总纲。每维度的「指标公式 + 取数口径 + 阈值 + 判据话术 + 图表规格」全文见 `references/dimensions.md`。执行时必须逐维跑完，不跳维，不用笔数代替金额。

| 维度 | 一句话 | 核心产出 |
|---|---|---|
| D1 金额与仓位真相 | 单笔金额与单笔/总市值比才是仓位真相（个人资金，非市场资金流） | 单笔分布、占比散点、周转率、充值节律 |
| D2 形态类型学 | 6-8 原型坐标落位，不硬分类 | HHI/Gini/重叠率、行业/风格/市值三切面、类型坐标 |
| D3 资金流三态 | 按池识别加仓/换仓/减仓（债当现金） | 三态日历、月度三态金额占比、场内外联动 |
| D4 换仓指纹 | 金额加权 + 五维合理性，不只笔数胜率 | 换仓对（按金额）、五维打分雷达、换入后表现 |
| D5 买卖点三源对齐 | 逐笔对齐当天技术+市场资金流+基本面三源快照 | 三源锚定度、K线标注、估值偏好雷达 |
| D6 阶段演进 | 多维行为向量变点，不预设剧本 | 变点时间轴、阶段定性卡片、习惯变迁表 |
| D7 金额加权归因 | 按钱算贡献，不按笔数 | 金额加权榜、大单小单分化、持仓时长收益 |
| D8 纪律与风险 | 扛单还是止损（含速度轴） | 摊薄深度、止损率、沉淀成本、处置效应 |
| D9 画像总括 | 把数字翻译成人话 | 一句话定性、雷达、优势/盲区、摘要段落 |

### 执行顺序（Workflow 流水线）

```
Phase 0 · 准备（主线程）
  D1(金额清洗+分池) → D2(形态·风险池) → D3(三态·按池) → D4(换仓·金额加权)
  产出：选样清单（持仓Top5 + 换仓高频Top3 + 归因Top3，去重约12只风险池标的）
  ↓
Phase 1 · 并行抽取（Workflow 4组，准确优先）
  Group-A: 2-3只 逐笔对齐 K线分位 + PE/PB/股息分位
  Group-B: 2-3只 同上
  Group-C: 2-3只 同上（ETF/港股预期空，标缺失）
  Group-D: 批量 get_fundflow / get_index_fundflow 按交易日去重（约150个 as_of）
  约束：每组只回固定 Schema 的 JSON 摘要（1-2KB/组），不回 raw；失败记覆盖率，不重试 refresh
  ↓
Phase 2 · 聚合（主线程，不并行）
  汇总4组摘要 → D5三源锚定度 → D6多维变点（方向/位置/资金流锚/估值锚/速度）
  → D7/D8(速度轴分群) → D9画像 → 组装 PDF
```

Phase 0 必须在 Workflow 前完成，选样与分池结果是 Phase 1 的输入；Phase 2 必须单线程聚合，保证口径一致与变点准确。

## 工具编排

- **Excel 解析**：`scripts/parse_excel.py` 统一入口，输出 `trades_clean.json / holdings_clean.json / closed_clean.json`，含 `pool=risk|cash` 标记
- **MCP 调用**：Workflow Phase 1 内按 `references/mcp-plan.md` 的 as_of 分组计划，分别拉 `get_kline`、`get_fundflow`/`get_index_fundflow`、`get_stock_detail(partial, as_of)`，带缓存与 409 补偿；禁止并发批量 `diagnose_stock`；禁止主线程全量堆 raw
- **变点检测**：`scripts/detect_phases.py` 对多维行为向量做 PELT（含技术/资金流/基本面锚定度 + 方向/位置/速度）
- **图表**：`scripts/charts.py` 产出 ECharts/Chart.js 配置，配色遵循 `references/palette.md`
- **报告**：`assets/report_template.html` 为骨架，`scripts/build_report.py` 注入数据后转 PDF（Chrome headless）

## 输出规格

- **主交付**：`portfolio-report-YYYYMMDD.pdf`（A4 可打印，浅色打印友好，深色预览自适应）
- **副交付**：`metrics.json`（全部三级指标，便于二次分析）+ `figures/`（单图 PNG）+ `phase1_summaries/`（4组摘要 JSON，可审计）
- 章节固定为 9 章，对应 D1-D9；每章「一主图 + 一结论句」，不堆表（见 `references/report-outline.md`）

## 配置参数化

所有阈值抽到 `config.yaml`，换表即调，不硬编码。含分池清单、波动权重、变点惩罚、Workflow 分组等。

## 质量门槛

- 金额口径必须验证：`买入额 + 卖出额 + 费用 ≈ 流水总额`，偏差>2% 则告警
- K线/估值/资金流覆盖率 <60% 时，D5 的结论必须标注「样本不足」
- 单池 HHI 必须与全池 HHI 同时报告，避免债稀释误判
- 变点检测惩罚项需做敏感性测试（±20%），变点不稳定则降为「趋势描述」而非「阶段定性」
- Phase 1 摘要必须经 `scripts/validate_report.py` 的 Schema 校验（字段缺失即重跑该组）
- 报告发布前跑 `scripts/validate_report.py` 检查图表与结论一致性
